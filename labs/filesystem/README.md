# Анализ /data

Приложение использует только встроенные модули Node.js. Рекурсивно считает обычные файлы, вложенные каталоги и суммарный размер файлов в байтах. Символьные ссылки игнорируются; корень `/data` не считается. При ошибке пишет сообщение только в stderr и возвращает ненулевой код.

Проверка:

```sh
node --test analyze.test.mjs
```

В сборке по умолчанию указан настоящий номер ИСУ `311553`. Он записывается внутрь образа; при запуске аргументы и переменные окружения не нужны:

```sh
docker build --platform linux/amd64 -t student-fs .
docker run --rm --network none --mount type=bind,source="$(pwd)/test-data",target=/data,readonly student-fs
```

Обычная команда `docker build -t student-fs .` также работает без дополнительных аргументов. Некорректное переопределение `--build-arg ISU=...` отклоняется. `000000` используется только в тестах и не является подписью студента.

Для сдачи нужен публичный образ `ghcr.io/<github-login>/itmo-component-lab:311553` для `linux/amd64`, у которого тег совпадает с номером в stdout. Исходный код или архив не заменяет имя опубликованного образа.
